## 二、发现并修复的 2 个生产 Bug

### Bug 1：api-gateway 不加载项目根目录 `.env`

| 项 | 详情 |
|---|---|
| **现象** | AUTH_REQUIRED 永远为 false（走代码默认值），即使 `.env` 里写了 AUTH_REQUIRED=true。JWT_SECRET 也走默认值 "secret" |
| **根因** | 启动脚本 `start_services.bat` 直接 `python app.py`，不通过 docker-compose 注入环境变量；app.py 里没有 `load_dotenv()` 逻辑 |
| **影响** | 所有生产配置（AUTH_REQUIRED、JWT_SECRET、CORS、限流阈值）在本地启动时全部失效 |
| **修复** | 在 `api-gateway/app.py` 顶部新增 `_load_root_dotenv()` 函数，从项目根目录 `.env` 读取配置（不覆盖已存在的环境变量）。ai-service/main.py 已有同名机制 |
| **验证** | 修复后 `Invoke-RestMethod /health` 返回 `auth_required: True`，网关启动时不再因账号表为空而报错（之前 AUTH_REQUIRED=false 绕过了这个检查） |

### Bug 2：security_middleware 拦截 CORS OPTIONS 预检请求

| 项 | 详情 |
|---|---|
| **现象** | 前端发带 Authorization header 的 POST（如 TTS 合成），浏览器报 `net::ERR_FAILED`，OPTIONS 预检返回 401 |
| **根因** | 浏览器跨域 + Authorization 时先发 OPTIONS 预检（不带 token）；security_middleware 在鉴权检查前没有跳过 OPTIONS 请求，直接返回 401 |
| **影响** | **所有**跨域带鉴权的前端请求全部失败（TTS、角色列表、会话角色、情感配置等） |
| **修复** | 在 `security_middleware` 函数开头新增 `if request.method == "OPTIONS": return await call_next(request)` |
| **验证** | 修复后 OPTIONS preflight 返回 200 + 完整 CORS 响应头，前端 TTS 合成成功返回 `blob:` audio |
