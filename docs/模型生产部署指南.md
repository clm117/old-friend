## 一、模型文件迁移与校验（任务 28）

### 模型清单
| 模型 | 大小 | 用途 | 存储路径 |
|------|------|------|---------|
| Fun-Audio-Chat-8B | ~16GB (fp16) | 语音对话 | /models/Fun-Audio-Chat-8B |
| VoxCPM2 | ~4.5GB | TTS 语音合成 | models/voxcpm2（仓库内） |

### 迁移步骤
```bash
# 1. 创建模型目录
sudo mkdir -p /models
sudo chown -R $USER:$USER /models

# 2. 从开发机同步（使用 rsync 或 scp）
rsync -avz --progress user@dev-machine:/path/to/models/ /models/

# 3. 校验哈希（防损坏）
cd /models
sha256sum Fun-Audio-Chat-8B/* > checksums.txt
sha256sum VoxCPM2/* >> checksums.txt

# 4. 验证
sha256sum -c checksums.txt
```

### Docker 挂载配置
```yaml
# docker-compose.yml
services:
  ai-service:
    volumes:
      - /models:/app/models:ro  # 只读挂载
```

## 二、显存占用实测（任务 29）

### 测试脚本
```python
# test_vram.py
import torch
import time

def test_vram_usage():
    """测试模型显存占用"""
    if not torch.cuda.is_available():
        print("无 CUDA 设备")
        return
    
    # 清空显存
    torch.cuda.empty_cache()
    
    # 记录初始显存
    initial = torch.cuda.memory_allocated() / 1024**3
    print(f"初始显存: {initial:.2f} GB")
    
    # 加载模型（示例）
    from transformers import AutoModelForCausalLM, AutoTokenizer
    
    model_name = "Fun-Audio-Chat-8B"
    tokenizer = AutoTokenizer.from_pretrained(model_name)
    model = AutoModelForCausalLM.from_pretrained(
        model_name,
        torch_dtype=torch.float16,
        device_map="auto"
    )
    
    # 记录加载后显存
    loaded = torch.cuda.memory_allocated() / 1024**3
    print(f"模型加载后: {loaded:.2f} GB")
    print(f"模型占用: {loaded - initial:.2f} GB")
    
    # 推理测试
    inputs = tokenizer("你好", return_tensors="pt").to("cuda")
    with torch.no_grad():
        outputs = model.generate(**inputs, max_length=50)
    
    peak = torch.cuda.max_memory_allocated() / 1024**3
    print(f"推理峰值: {peak:.2f} GB")
    
    # 清理
    del model
    torch.cuda.empty_cache()

if __name__ == "__main__":
    test_vram_usage()
```

### 显存要求
| 模型 | 显存占用 | 建议余量 | 最小显存 |
|------|---------|---------|---------|
| Fun-Audio-Chat-8B fp16 | ~16GB | 4GB | 20GB |
| VoxCPM2 | ~4.5GB | 2GB | 6.5GB |
| **合计** | **~20.5GB** | **6GB** | **26.5GB** |

**结论**：需要 **24GB+ 显存** 的 GPU（RTX 3090/4090/A10）

## 三、加载策略与启动预热（任务 30）

### 懒加载 vs 预加载

**懒加载（当前方案）**
- 优点：启动快、按需加载
- 缺点：首次请求慢（模型加载 30-60s）

**预加载（生产推荐）**
```python
# ai-service/main.py
@app.on_event("startup")
async def startup_event():
    """启动时预加载模型"""
    logger.info("开始预加载模型...")
    
    # 预热 VoxCPM2
    if _USE_GPU:
        voxcpm2_service.warmup()
    
    # 预热 LLM
    llm_service.warmup()
    
    logger.info("模型预加载完成")
```

### 分卡部署（多 GPU 场景）
```python
# 模型分配到不同 GPU
import torch

if torch.cuda.device_count() >= 2:
    # GPU 0: LLM
    llm_device = torch.device("cuda:0")
    # GPU 1: TTS
    tts_device = torch.device("cuda:1")
else:
    # 单卡共享
    llm_device = tts_device = torch.device("cuda:0")
```

## 四、推理并发与排队（任务 31）

### 当前实现

本仓库**没有独立的队列模块**（不存在 `queue_manager.py`），推理并发由运行方式决定：

- 本地 CPU 版：`ai-service/main.py` 的 `_synthesize_speech` 把同步推理放进线程池执行，避免阻塞事件循环；
- 本地 GPU 版：`voxcpm2/voxcpm2_service_gpu.py` 为异步合成，按事件循环并发；
- 需要限制并发时，在网关层做限流（`api-gateway/app.py` 已按普通/昂贵桶限流），不要假设服务内有 `InferenceQueue` 或状态端点。

### 超时策略

AI 服务不设置固定推理超时；超时统一由网关控制：

```bash
# api-gateway/app.py
AI_SERVICE_TIMEOUT=60   # 秒，环境变量可调；`_async_request` 默认使用该值
```

超时或上游不可达时，网关返回 `502` 与统一文案「服务暂时不可用，请稍后重试」（`_upstream_error`）。

## 五、降级与熔断（任务 32）

### 当前实现

本仓库**没有通用熔断器**（不存在 `circuit_breaker.py`），降级按真实错误码透传，不做"假成功"：

- 云 TTS / 声音定义失败：`cloud_tts_service`、`cloud_voice_service` 将 402（欠费）、429（限流）、5xx 映射为明确错误码（如 `voice_quota_unavailable`、`voice_quota_exhausted`），AI 服务返回对应 HTTP 状态；
- 网关层：上游不可达或超时 → `502` + 统一文案，客户端可区分"服务不可用"；
- LLM 失败：`llm_service` 返回受控错误，WebSocket 推送 `error` 消息，前端展示后解锁输入；
- 不内置"预设文案兜底"，避免把失败伪装成正常回复。

## 六、GPU 监控与显存告警（任务 33）

### 监控指标

指标实际定义在 `ai-service/main.py`，抓取端点为 `GET /metrics`（Prometheus 文本格式）：

| 指标名 | 类型 | 标签 | 说明 |
|---|---|---|---|
| `ai_requests_total` | Counter | endpoint, status | 请求计数 |
| `ai_request_duration_seconds` | Histogram | endpoint | 请求耗时（0.5s–600s 分桶） |
| `ai_gpu_memory_used_bytes` | Gauge | device | 显存已用字节 |
| `ai_gpu_memory_total_bytes` | Gauge | device | 显存总量字节 |

```python
# ai-service/main.py（节选）
AI_REQUESTS = Counter("ai_requests_total", "AI 请求总数", ["endpoint", "status"])
AI_LATENCY = Histogram("ai_request_duration_seconds", "AI 请求耗时", ["endpoint"],
                       buckets=[0.5, 1.0, 2.0, 5.0, 10.0, 30.0, 60.0, 120.0, 300.0, 600.0])
GPU_MEMORY_USED = Gauge("ai_gpu_memory_used_bytes", "GPU 显存已用字节数", ["device"])
GPU_MEMORY_TOTAL = Gauge("ai_gpu_memory_total_bytes", "GPU 显存总字节数", ["device"])
```

### 显存采集

没有常驻的 `gpu_monitor.py` 线程；显存在每次抓取 `/metrics` 时读取一次：

```python
@app.get("/metrics")
async def metrics():
    if _USE_GPU and torch.cuda.is_available():
        for i in range(torch.cuda.device_count()):
            GPU_MEMORY_USED.labels(device=f"cuda:{i}").set(torch.cuda.memory_allocated(i))
            GPU_MEMORY_TOTAL.labels(device=f"cuda:{i}").set(
                torch.cuda.get_device_properties(i).total_memory)
    return Response(generate_latest(), media_type=CONTENT_TYPE_LATEST)
```

显存告警请在 Prometheus 侧配置规则（如 `ai_gpu_memory_used_bytes / ai_gpu_memory_total_bytes > 0.9`），服务端不内置阈值日志。
