## 三、远程 GPU 执行方案

### 3.1 资源要求

| 项 | 最低 | 推荐 |
|---|---|---|
| GPU 显存 | 8 GB（仅 VoxCPM2） | 24 GB（VoxCPM2 + Fun-Audio-Chat-8B） |
| GPU 型号 | T4 / V100 | A10 / RTX 4090 / V100 32GB |
| 系统 | Ubuntu 22.04 | Ubuntu 22.04 |
| 磁盘 | 30 GB 空闲 | 80 GB 空闲 |
| Python | 3.11 | 3.11 |
| 其他 | 可访问公网（拉依赖） | 可访问 DashScope（LLM/ASR） |

说明：VoxCPM2 单独推理约 4.5-6.5 GB 显存；《模型生产部署指南》中 24GB+ 的要求是按“TTS + 8B 语音对话模型同时常驻”估算。

### 3.2 环境准备（Ubuntu 22.04 宿主机 / 容器方案）

```bash
# 1) NVIDIA 驱动（按实例实际型号选择 535+）
sudo apt update && sudo apt install -y nvidia-driver-535
sudo reboot
nvidia-smi

# 2) NVIDIA Container Toolkit（使用新的 libnvidia-container 仓库）
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
  | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
  | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' \
  | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt update && sudo apt install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker

# 3) 验证 GPU 已透传
sudo docker run --rm --gpus all nvidia/cuda:12.1-base nvidia-smi
```

> PAI-DSW 实例通常**不提供 Docker**，此时跳过第 2 步，直接使用实例自带 Python/Conda 运行服务（见 3.4 的“非容器方式”）。

### 3.3 模型与依赖

```bash
# 在 GPU 主机创建目录
sudo mkdir -p /opt/yuban/models /opt/yuban/data /opt/yuban/logs
sudo chown -R $USER:$USER /opt/yuban

# 从开发机同步（4.62 GB，千兆内网约 1 分钟；公网 10 Mbps 约 1 小时）
rsync -avz --progress models/voxcpm2/ user@gpu-host:/opt/yuban/models/voxcpm2/
# 如需本地语音对话
# rsync -avz --progress models/fun-audio-chat-8b/ user@gpu-host:/opt/yuban/models/fun-audio-chat-8b/

# Python 依赖（非容器方式）
python3.11 -m venv /opt/yuban/venv
source /opt/yuban/venv/bin/activate
pip install --upgrade pip
pip install torch torchaudio --index-url https://download.pytorch.org/whl/cu121
pip install -r ai-service/requirements.txt -c constraints.txt
pip install requests websockets
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

### 3.4 启动服务

**容器方式（推荐，与生产一致）**

```bash
# V100/较旧驱动需覆盖基础镜像
export AI_BASE_IMAGE=pytorch/pytorch:2.5.1-cuda12.1-cudnn9-runtime
export TTS_PROVIDER=voxcpm2
export LLM_PROVIDER=qwen
export LLM_API_KEY=<DashScope Key>
export AUTH_SEED_PASSWORD=<仅网关初始化需要>
docker compose up -d --build ai-service
docker compose logs -f ai-service
curl -s http://127.0.0.1:8084/health
curl -s http://127.0.0.1:8084/ready
```

**非容器方式（DSW 等无 Docker 环境）**

```bash
cd ai-service
export TTS_PROVIDER=voxcpm2
export LLM_PROVIDER=qwen
export LLM_API_KEY=<DashScope Key>
export YUBAN_DATA_DIR=/opt/yuban/data
export YUBAN_STATE_FILE=/opt/yuban/data/state.json
export CORS_ALLOW_ORIGINS=http://localhost:8899
nohup python -m uvicorn main:app --host 0.0.0.0 --port 8084 > /opt/yuban/logs/ai.log 2>&1 &
```

注意：代码按“项目根/models/voxcpm2”解析模型路径，因此需在仓库根目录或其等价结构下启动；容器内为 `/app/ai-service` + `/app/models`。

### 3.5 逐项验证

```bash
# 1) 只做预检（本机/远端均可）
python infrastructure/gpu/verify_gpu_chain.py --preflight-only

# 2) 全链路（直连 AI 服务，避免网关限流干扰）
python infrastructure/gpu/verify_gpu_chain.py --base http://127.0.0.1:8084 --out gpu_report.json

# 3) 经网关（自动处理 429，记录重试次数，不把 429 当故障）
python infrastructure/gpu/verify_gpu_chain.py --base http://127.0.0.1:8005 --token <JWT> --out gpu_report_gateway.json

# 4) 不需要 WS / 并发时可按需裁剪
python infrastructure/gpu/verify_gpu_chain.py --skip-ws --skip-concurrency
```

脚本覆盖：预检、声音定义/克隆、冷启动与稳态 TTS、长文本分句、WebSocket 端到端、并发 1/2/4。任何失败都会记录 `ok=false` 与错误原因，不会伪造通过。

**冷启动与稳态的区分**：`_ensure_model()` 首次请求才加载模型，GPU 版 `optimize=True` 会触发 `torch.compile`，首次 TTS 包含编译耗时；脚本把第一次请求标记为 `cold_start`，其后 3 次为稳态。进程启动到 `/ready` 的时间建议在启动命令外层用 `time` 单独记录：

```bash
/usr/bin/time -f "startup_to_ready=%e s" bash -c 'until curl -sf http://127.0.0.1:8084/ready >/dev/null; do sleep 1; done'
```

## 四、DashScope 欠费影响与可下线依赖

- **本地 GPU TTS 路径不受欠费影响**：`TTS_PROVIDER=voxcpm2` 时走本地模型，不调用 DashScope TTS。
- **仍受影响的云端依赖**：
  - LLM（`LLM_PROVIDER=qwen`，DashScope `compatible-mode`）：对话文本生成会失败，进而影响 WS 端到端与多句 TTS 编排。
  - ASR（`paraformer-realtime-v2`，复用同一个 `LLM_API_KEY`）：语音输入转写会失败。
- 因此切到本地 TTS 后**可以下线**：云 TTS 相关配置与费用（`CLOUD_TTS_*`、DashScope TTS 调用）；**不能下线**：若继续使用云 LLM/ASR，仍需有效的 DashScope Key 与余额。
- 若要完全摆脱 DashScope：需把 LLM 换成本地模型或第三方（`LLM_PROVIDER=glm/deepseek` 需要对应 Key），并把 ASR 接到本地 `models/whisper-medium`（当前 `asr_service.py` 尚未接本地 Whisper，属于新增改造，不在本次验证范围）。
- 本次 WS 端到端验证需要可用 LLM；若 DashScope 仍欠费，WS 用例会记录失败原因，不会伪造通过。

## 五、付费 GPU 与额度（需用户确认后才开机）

- PAI-DSW CU 单价约 **14.553 CU/小时**；250 CU/月约 **17.18 小时**。
- 首次验证预计 **3-4 小时**（含镜像拉取/构建、模型传输 4.62 GB、首次 `torch.compile`、逐项测试与 1/2/4 并发），约消耗 **44-58 CU（月额度 18%-23%）**。
- 若模型已在实例本地、镜像已缓存，可压缩到约 **2-2.5 小时（29-36 CU）**。
- 本方案**不自动开机、不自动扣费**。执行前后均需：
  1. 开机前确认实例规格、计费方式与剩余 CU；
  2. 验证完立即关机/停止实例；
  3. 记录实际开机时长与 CU 消耗，回填到验证报告。
